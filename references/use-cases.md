# Use-case catalogue: configurations this skill has actually run on

Use these as precedents when a request resembles one. Subject names are generic; no person, institution or course is recorded. Sizes are finished pages. "Cap" is the user's or planned `page_cap`.
Contents: Origin runs - Recent runs (10 books) - Patterns across all of them

## Origin runs (the skill was written from these; not re-mined)
Two 100+ page textbooks on parallel and high-performance computing, built by hand from lecture slides, scanned pages and a reference book, then NoSQL databases (code-heavy; this is where the back-of-book index came
from), control systems and operations research. They fixed the base design: classic running heads, uniform figures, worked examples, end-of-chapter questions with full solutions, page cap, identity scrub.

## Patterns across all of them
* At least three users went away right after the request (one said so, one left a question round unanswered for ten hours, one returned after 2.5 hours): the skill must run on stated defaults and report its assumptions afterwards.
* Nine of the ten runs asked for, or chose, identity removal; none objected to it. Hidden-by-default saves a second build.
* Six users, after seeing a finished book, said or asked whether everything supplied was in it. Completeness is the first quality, proven by a ledger.
* Past papers drove four of the ten runs (six books); in several they were first mentioned only after the first build. Ask for them at the start.
* Page caps were wrong in both directions (73 pp against 120-150; 214 pp against 120). Ceilings, a density lever and an early size estimate settle it.
* Three runs used a start number other than 1 (3, 4, 4), one of them as an excerpt with first folio 88.
* The tools' false alarms (substring identity hits, appendix gap flags, locked PDF) each cost a manual workaround that bypassed a gate; they are fixed, and the instruction now is to say so when a gate is overridden.
